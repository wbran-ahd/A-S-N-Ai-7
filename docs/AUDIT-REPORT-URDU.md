# صوتی بقیہ — موجودہ حالت کا فنی جائزہ

> **پروجیکٹ:** صوتی بقیہ (`sauti-baqaya` v1.0.0) — اردو وائس فنانس اسسٹنٹ (PWA)
> **اسٹیک:** React 19 + TypeScript 5.9 + Vite 7 + Tailwind CSS 4 + Firebase 13 (Auth / Firestore / Functions)
> **بیک اینڈ:** صرف Firebase — Convex مکمل طور پر ہٹا دیا گیا (`docs/adr-dual-backend.md`)
> **تازہ کاری:** یہ دستاویز پرانے آڈٹ کی جگہ لیتی ہے۔ پرانی فائل میں مشینی اور بےمعنی
> جملے تھے اور اس میں ایسی کمزوریاں "کھلی" بتائی گئی تھیں جو کوڈ میں پہلے ہی درست ہو چکی
> ہیں — اس لیے اسے مکمل طور پر بدل دیا گیا ہے۔

---

## 1. تصدیق شدہ حالت

| چیک | نتیجہ |
|---|---|
| `bun run typecheck` | ✅ صاف |
| `bun run build` | ✅ کامیاب |
| `bun run test` (منطق کے اسکرپٹس) | ✅ 275 سے زائد چیک |
| `bun run test:unit` (Vitest) | ✅ reducer، sync planning، اردو گرامر |
| `bun run size` | ✅ بجٹ کے اندر |

اعداد و شمار ہر ریلیز پر دوبارہ چلائے جاتے ہیں؛ یہاں کوئی اندازہ نہیں لکھا جاتا۔

---

## 2. معمار (Architecture)

```
src/
  main.tsx                 ایپ شیل، روٹس، بعد از پینٹ observability
  pages/KhataApp.tsx       کمپوزیشن لیئر (state خود ہوکس میں)
  hooks/                   use-khata (ریکارڈ)، use-sync (Firebase)، staff، PWA، voice
  features/                ledger، analytics، settings، shop، ai-advisor، onboarding
  lib/                     خالص منطق: khata، insights، parties، i18n، tts، ai، voice-grammar
functions/index.js         Firebase Cloud Function: AI تجزیہ + روزانہ حد
```

**اصول:**

1. ہر ریکارڈ کی تبدیلی ایک ہی ریڈیوسر (`khataReducer`) سے گزرتی ہے — آواز، دستی، درآمد،
   خودکار اندراج سب کے لیے یکساں۔
2. Firestore ہی واحد ڈیٹا اسٹور ہے؛ تصدیق anonymous Firebase سیشن سے ہوتی ہے اور ہر
   دستاویز `users/{uid}` کے نیچے رہتی ہے۔
3. AI کی چابی سرور پر ہے (`functions/`)، کلائنٹ صرف callable فنکشن بلاتا ہے۔

---

## 3. ڈیٹا کی حفاظت

- **firestore.rules:** ڈیفالٹ deny، مالک کی شرط، ہر فیلڈ کی قسم/لمبائی کی جانچ، اور
  tombstone کو دوبارہ زندہ ہونے سے روکنے والے قوانین۔ حذف "جگہ پر" ہوتا ہے، دستاویز
  مٹائی نہیں جاتی، تاکہ دوسرے آلے بھی حذف دیکھ سکیں۔
- **اپ لوڈ منصوبہ (`planUpload`):** پہلے کلاؤڈ پڑھا جاتا ہے، پھر فیصلہ؛ موبائل سے پرانا
  ڈیٹا نئے کلاؤڈ ڈیٹا کو نہیں لکھ سکتا، دوبارہ کوشش idempotent ہے، اور tombstone پر
  کبھی نہیں لکھا جاتا۔
- **ڈاؤن لوڈ ضم (`mergeCloudRows`):** کوئی ریکارڈ ضائع نہیں ہوتا، یہ ڈیوائس پر حذف شدہ
  واپس نہیں آتا، خراب payload آنے پر مقامی کھاتہ ویسے کا ویسا رہتا ہے۔
- **بحالی:** سات دن تک «حالیہ حذف شدہ» فہرست سے ایک ٹیپ بحالی۔ بحالی **نئی** انٹری
  بناتی ہے (نئی id) کیونکہ قوانین tombstone زندہ کرنے کی اجازت نہیں دیتے — یہی محفوظ
  راستہ ہے۔

**بقایا خطرہ:** 1000 فی قسم ریکارڈ کے بعد پرانا کھاتہ کلاؤڈ پر نہیں جاتا۔ اب یہ حد
اسکرین پر دکھائی جاتی ہے اور «آرکائیو کریں» سے فائل محفوظ کی جا سکتی ہے، مگر خودکار
آرکائیو نہیں ہے۔

## 4. سیکیورٹی

- **CSP:** پروڈکشن بلڈ میں مکمل پالیسی شامل ہوتی ہے (`vite.config.ts` → `cspPlugin`)؛
  ڈویلپمنٹ میں نہیں، کیونکہ وہاں react-refresh کا inline اسکرپٹ درکار ہے۔
- **سورس میپ:** بلڈ `sourcemap: 'hidden'` سے میپ بناتا ہے، مگر `scripts/finalize-dist.mjs`
  انہیں (Sentry کے لیے، اگر token ہو) اپ لوڈ کر کے **ڈیلیٹ** کر دیتا ہے؛
  `bun run verify:nomaps` CI اور ڈیپلائے دونوں میں گیٹ ہے۔ `firebase.json` کا
  `**/*.map` ignore صرف دوسری تہہ ہے — `deploy/manifest.json` پورا `dist` اپ لوڈ کرتا ہے،
  اس لیے اصل ضمانت فائل کا موجود نہ ہونا ہے۔
- **ذاتی چابی:** صرف ڈیوائس کے `localStorage` میں؛ Firestore پر صاف متن میں کبھی نہیں
  لکھی جاتی۔
- **AI حد:** سرور پر `getAiQuota` پہلے چیک ہوتی ہے، اور `spendQuota` صرف کامیاب جواب کے
  بعد — ناکام کال quota نہیں جلاتی۔
- **سیلز مین PIN:** نمک کے ساتھ SHA-256، اور پانچ غلط کوششوں کے بعد 60 سیکنڈ کی روک
  (`staff-lock.ts`)۔ یہ دکان کی سہولت ہے، اکاؤنٹ کی حفاظت نہیں — UI بھی یہی کہتا ہے۔
- **Host allowlist:** ڈیو سرور اب صرف loopback اور `VITE_ALLOWED_HOSTS` میں دیے گئے
  hosts قبول کرتا ہے (`allowedHosts: true` ہٹا دیا گیا)۔

---

## 5. کارکردگی

- انٹری چنک کے لیے بجٹ CI میں نافذ ہے (`scripts/check-bundle-size.mjs`)۔
- Firebase، Sentry، PostHog، vly، چارٹس اور اب **رپورٹنگ/nxlsx** بھی on-demand لوڈ ہوتے ہیں۔
- FontAwesome CSS اب render-blocking نہیں: `deferred-icons.ts` اسے غیر مسدود طریقے سے
  لوڈ کرتا ہے۔
- خود میزبان Nastaliq فونٹ preload ہے؛ کوئی تیسرا CDN نہیں۔

**بقایا:** FontAwesome کے webfonts اب بھی ڈاؤن لوڈ ہوتے ہیں۔ مکمل حل یہ ہے کہ استعمال
شدہ چند آئیکن inline SVG میں بدل دیے جائیں (اگلا مرحلہ)۔

---

## 6. رسائی اور اردو

- `dir="rtl"`، `lang="ur"`، اردو ہندسوں کا اختیار، اردو TTS، مکمل manifest۔
- **متن کا سائز:** عام / بڑا / بہت بڑا — صرف root font-size بدلتا ہے، ترتیب نہیں۔
- ہلکے متن (white/40–50) کا contrast دھوپ کے لیے بڑھا دیا گیا۔
- cloud حالت، AI کی حد اور الرٹس `aria-live` کے ذریعے سنائی دیتے ہیں۔
- ماڈلز میں focus trap، Escape اور `aria-modal` پہلے سے موجود ہیں۔

## 7. آواز

- آواز کی سہولت نہ ہو (Safari/iOS) تو مائیک خاموش نہیں رہتا: اردو وضاحت، ٹوسٹ، اور
  لکھ کر درج کرنے کی ہدایت۔
- **اصلاح گرامر:** «نہیں، پچاس نہیں دو سو» زیرِ تصدیق رقم بدل دیتا ہے
  (`src/lib/voice-grammar.ts`، ٹیسٹ شدہ)۔
- پیمائش: `speech_entry_edited` واقعہ بتاتا ہے کہ آواز سے درج انٹری کتنی دیر بعد
  درست کی گئی — یہی آواز کی اصل درستگی کا پیمانہ ہے۔

---

## 8. ٹیسٹنگ

| پرت | حیثیت |
|---|---|
| `scripts/verify-*.ts` | خالص منطق: رقم، بجٹ، CSV، sync safety، parties، scaffolding |
| `tests/unit` (Vitest) | reducer، upload/merge planning، اردو گرامر |
| `tests/e2e` (Playwright) | add → undo → CSV ڈاؤن لوڈ (CI میں `E2E=true` پر) |

**بقایا:** براؤزر میں E2E اس ماحول میں نہیں چلایا گیا؛ اسے `bunx playwright install
chromium` کے بعد چلانا ہوگا۔

---

## 9. اگلے مرحلے (ترجیح کے مطابق)

1. FontAwesome کی جگہ inline SVG (آئیکن فلیش اور 300 kB webfonts کا خاتمہ)۔
2. خودکار آرکائیو: حد پوری ہونے پر پرانے مہینے خود فائل میں محفوظ ہوں۔
3. Firestore rules کے emulator ٹیسٹ CI میں، تاکہ قوانین کی تبدیلی محفوظ رہے۔
4. Sentry کا release/DSN خودکار سیٹ کرنا، تاکہ stack traces اصل لائن نمبر دکھائیں (میپ
   اپ لوڈ کا راستہ تیار ہے؛ صرف secrets اور `VITE_SENTRY_DSN` درکار ہیں)۔
5. آواز کی درستگی کی رپورٹ: کن الفاظ پر سب سے زیادہ تصحیح ہوتی ہے۔
